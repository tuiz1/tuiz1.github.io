# VPN 与机场服务风险分析

> 隧道出口必然能看到解包后的内容——这是物理事实。真正的安全问题不是"会不会被看到"，而是"被谁看到、这个人受什么约束"。

---

## 一、先搞清楚：VPN / 机场到底能看到什么？

从网络层级来看，不管二层、三层还是四层代理，**隧道出口解密后都能看到 TCP 头和 HTTP 载荷**。层级只决定封装范围，不决定可见性：

```
二层 VPN (TAP)：  解密后  [ETH头 │ IP头 │ TCP头 │ 载荷]
三层 VPN (TUN)：  解密后          [IP头 │ TCP头 │ 载荷]
四层 SOCKS5：     直接持有 TCP            [TCP头 │ 载荷]
HTTP 代理：       解析 HTTP                      [HTTP头+体]
```

真正决定可见性的是 **TLS，不是 VPN 层级**：

| 场景 | 机场/VPN 能看到什么 |
|---|---|
| HTTP 明文 | URL、表单、Cookie——全部可读 |
| HTTPS (TLS) | 目标 IP、域名（SNI）、流量大小、时间——**内容不可读** |
| 安装了机场的 CA 证书 | HTTPS 也被解密——等同于 HTTP 明文 |

## 二、风险清单

### 风险 1：元数据全量暴露

机场同时扮演隧道出口和你的 DNS——它能看到比 ISP 更多的信息：

```
机场的视角：
  你的真实 IP              → 地理位置
  每个目标 IP + 端口        → 你在访问什么服务、用什么协议
  每次连接的精确时间         → 作息模式
  DNS 查询                 → 你查了哪些域名（如果 DNS 走机场）
  TLS SNI                  → 即使 DNS 加密了，SNI 仍然暴露域名
  流量大小和方向            → 下载还是上传？看视频还是浏览网页？
```

> 元数据通常比内容更有情报价值。"谁、何时、跟谁、多久"比"说了什么"更能揭示行为模式。

### 风险 2：流量劫持与篡改

机场是你所有流量的唯一中转点，技术上有能力：

```
劫持类型：
  DNS 污染       → 你查 baidu.com → 机场 DNS 返回假的 IP
  注入脚本       → HTTP 明文网站可被注入 JavaScript、广告
  降级攻击       → 阻断 HTTPS → 浏览器降级到 HTTP → 明文暴露
  重定向         → 访问 google.com → 被引到钓鱼页面
  内容过滤       → 选择性屏蔽或放行 → 你得到的不是完整的互联网
```

### 风险 3：TLS 中间人攻击

正常情况下机场不能解密 HTTPS。以下情况除外：

```
条件 1：你安装了机场提供的 CA 证书
  → 机场可以签发任意域名的伪造证书
  → 浏览器信任它（因为你导入了根）
  → 所有的 HTTPS 内容被机场透明地解密-重加密
  → 你完全感知不到

条件 2：网站没用 HSTS
  → 机场阻断 443 端口 → 浏览器降级到 HTTP → 明文暴露

条件 3：机场自己的闭源客户端
  → 可以内置根证书、修改系统代理、收集设备信息
  → 你无法审计
```

> 如果机场让你安装了任何证书或跑了任何闭源客户端，假定所有流量可被解密。

### 风险 4：客户端软件风险

这是最容易被忽视的攻击面。以开源 vs 闭源分别分析：

**闭源客户端（机场自研 App）**：

```
拥有你设备的权限 → 可以：
  → 读取系统信息、已安装应用列表
  → 读取浏览器 Cookie、历史、保存的密码
  → 静默更新：今天没恶意 ≠ 明天没恶意
  → 持久化：开机自启、隐藏进程
  → 作为跳板：你的设备变成机场网络中继节点
```

**开源客户端（Clash / v2rayN / Sing-Box）**：

```
相对安全，但也不是零风险：

  FlClash 具体问题：
    → 单人维护（chen08209），贡献者只有 3 人，审计带宽极窄
    → v0.8.86 存在已知 DNS 泄漏漏洞（DNS 走直连，ISP 可见）
    → 内置 JS 引擎（flutter_js）——机场订阅配置可以包含 JavaScript
       → 如果导入了恶意配置，可以执行任意代码
    → Windows 版本无数字签名，无法验证二进制是否被篡改
    → TUN 模式需要管理员权限 + HelperService 常驻

  Clash Verge / mihomo：
    → 维护更活跃，贡献者更多
    → 但 JS 配置执行同样是攻击面
    → 内核和 GUI 分离 → 内核可以单独更新和审计
```

### 风险 5：传输链条不透明

机场行业多级转售是常态：

```
一级（有服务器、带宽）→ 二级（大批发）→ 三级（你的"机场"）

每一跳增加：
  → 多一个人可以看到你的元数据
  → 多一个可能记录日志的节点
  → 多一个可能被查封/跑路的环节
  → 你完全不知道链条上跑了什么软件
```

你的实际隧道可能长这样：

```
你 ═══ 机场 ═══ ? ═══ ? ═══ 目标
                  │       │
            中转节点是谁？跑什么软件？记录日志吗？你跟它没有直接关系。
```

### 风险 6：路由模式也有风险——全局 vs 规则 vs 直连

```
全局模式：
  所有流量进隧道 → 国内网站绕路（延迟暴涨）
  → 且所有流量暴露给机场 → 隐私风险最高

规则模式：
  按域名/IP 匹配 → 国内直连、国外代理
  → 规则不完善时有"漏代理"风险：该走的没走，ISP 能看到
  → 也有"误代理"风险：不该走的走了，国内网站流量暴露给机场
  → 规则集由社区维护 → 可能被投毒

直连模式：
  等同于关闭代理 → 无隐私保护
  → 但临时切换时可能会忘记切回来
```

### 风险 7：数据留存——机场比 ISP 更无约束

```
ISP（中国电信/联通/移动）：
  → 法律强制留存日志 ≥ 6 个月
  → 受严格监管，滥用有法律后果
  → 大型国企，有公开责任主体

机场：
  → 无法律义务告诉你它存了什么
  → 无监管机构约束数据使用
  → 责任主体不明——"跑路"是行业常态
  → 境外经营 → 中国法律无法追责
  → 境内经营 → 随时被执法部门查封，数据被没收
```

> 核心悖论：你选机场是为了不让 ISP 看。但机场比 ISP 更不透明、更不受约束。你从"受监管的可见"变成了"无监管的可见"。

### 风险 8：付款关联身份

```
微信/支付宝  → 直接关联实名
加密货币     → 匿名性较好，但交易所 KYC 可能关联
礼品卡       → 相对匿名，购买渠道仍可能留痕

即使付款匿名：
  → 每次连接暴露真实 IP
  → 浏览器指纹（User-Agent、分辨率、字体、WebGL）可被关联
  → 同一浏览器访问机场网站 + 登录百度/微信 → 身份被交叉比对
```

## 三、风险矩阵

| 风险维度 | 机场 | 自建 VPS + WireGuard | ISP 直连 |
|---|---|---|---|
| 元数据暴露 | 全部给机场 | 给 VPS 厂商+机房 | 给 ISP |
| 流量劫持 | **高**（无监管） | 低（你控制软件） | 低（法律约束） |
| TLS 中间人 | **中高**（客户端风险） | 极低（你控制两端） | 极低 |
| 客户端安全 | 看是否闭源 | 开源，可审计 | 无额外客户端 |
| 数据留存 | **未知**（无约束） | VPS 厂商可能有 | 法定留存 |
| 链条透明度 | **无**（多级转售） | 完全透明 | 完全透明 |
| 付款匿名 | 取决于方式 | 加密货币可选 | 宽带实名 |
| 跑路风险 | **高** | 无 | 无 |
| DNS 泄漏风险 | **中**（客户端bug） | 极低 | 无代理 |

## 四、如果你仍然需要使用机场

```
必须做：
  1. 不要装机场提供的任何 CA 证书
  2. 不要用机场的闭源客户端 → 用开源（Clash / v2rayN / Sing-Box）
  3. 不导入不可信来源的订阅配置（JS 脚本是攻击面）
  4. 浏览器强制 HTTPS-Only
  5. DNS 走 DoH/DoT，不依赖机场 DNS
  6. 不在机场网络上登录银行/支付/身份相关网站

建议做：
  7. 付款方式跟日常身份隔离（不用微信/支付宝实名账户）
  8. 定期检查客户端版本是否有已知漏洞
  9. 不用 TUN 模式时关闭 HelperService
  10. 审计订阅配置：查有没有可疑的 JS 脚本、异常的规则条目
```

## 五、回到原点

> 机场解决的是"ISP 能看到我的流量"。但它引入了一个更大的问题：**机场能看到我的流量，而我对它没有任何约束能力。**

从网络第一性原理看，隧道出口**必然**能解密并看到所有经过它的数据包。这是物理事实——不是机场的错。真正的安全问题是信任链条：

```
ISP：受法律约束，但也受法律强制 → 你不知道它拿你的数据做了什么
机场：不受法律约束，也不受法律保护 → 你不知道它拿了你的什么数据
自建：你控制一切，但也承担一切 → 你知道风险在哪
```

三种选择都是"不完美的信任"。区别在于：**你能准确说出你信任了谁、他们受什么约束、出事了你能找谁。** 对于机场，这三个问题都回答不了。
